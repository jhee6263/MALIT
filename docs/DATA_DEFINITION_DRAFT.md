# 말이음 데이터 정의 초안

> 상태: 검토 중 · 아직 실제 사용자/환자/훈련 콘텐츠를 등록하지 않음

## 1. 계정 표기 원칙

로그인 정보와 화면 표시 이름을 분리한다.

| 역할 | 로그인 방식 | 화면 표시 이름 | 예시 |
|---|---|---|---|
| 관리자 | 실제 이메일 | 실제 이름 | 이메일: 본인 이메일 / 이름: 이진희 |
| 재활사 | 실제 이메일 | 이름 또는 테스트용 별칭 | 이메일: 실제 이메일 / 이름: 김재활사01 |
| 환자 | 짧은 로그인 아이디 | 테스트용 별칭 | 아이디: patient01 / 이름: 김환자01 |

### 권장 테스트 이름

- 재활사: `김재활사01`, `김재활사02`
- 환자: `김환자01`, `김환자02`
- 환자 로그인 아이디: `patient01`, `patient02`

번호를 두 자리로 통일하면 정렬과 검색이 쉽다.

## 2. 이메일 사용 원칙

### 관리자·재활사

이메일 확인과 비밀번호 재설정을 위해 실제 수신 가능한 이메일을 사용한다. 여러 테스트 계정이 필요하면 Gmail 별칭 방식처럼 `본인이메일+therapist01@gmail.com` 형태를 사용할 수 있다.

`therapist01@example.com`은 화면 확인에는 알아보기 쉽지만 실제 인증 메일을 받을 수 없으므로 이메일 인증을 사용하는 환경에는 적합하지 않다.

### 환자

환자는 이메일을 직접 입력하지 않는다. 화면에서는 `patient01` 같은 로그인 아이디만 사용한다. Supabase Auth 내부 이메일은 앱이 자동 생성하며 환자에게 노출하지 않는다.

제안 형식:

```text
환자 로그인 아이디: patient01
내부 Auth 이메일: patient01@patient.malit.example
화면 표시 이름: 김환자01
```

서비스 이름이 말이음(MALIUM)으로 바뀌었지만 내부 이메일 도메인은 기존 환자 계정과 맞추기 위해 `patient.malit.example`을 유지한다.

## 3. 역할별 생성 과정

```text
최초 관리자
→ Supabase에서 1회 직접 생성

재활사
→ 웹 회원가입
→ profiles.status = pending
→ 관리자 승인
→ profiles.status = active

환자
→ 승인된 재활사가 등록
→ Auth 계정과 profiles 생성
→ therapist_patient_links 연결
→ learner_settings 초기 설정
```

## 4. 테이블별 필수 데이터

### profiles

| 필드 | 설명 |
|---|---|
| id | Supabase Auth 사용자 UUID |
| login_id | 환자용 로그인 아이디. 관리자·재활사는 비워둠 |
| name | 화면에 표시할 이름 |
| role | admin / therapist / patient |
| status | pending / active / rejected / suspended |
| organization | 재활사 소속 기관 |
| credential | 재활사 자격 정보 |

현재 스키마에는 `login_id`가 없으므로 최종 합의 후 추가 마이그레이션이 필요하다.

### learner_settings

- 환자 UUID
- 시작 훈련 Level
- 하루 문장 수
- 포함할 훈련 주제
- 제외할 훈련 주제
- 기본 반응 대기 시간

### topics

훈련 주제는 사용자 계정과 별도로 먼저 정의한다. 확정 전에는 자동으로 삽입하지 않는다.

### training_contents

- Level
- 주제
- 상황 이미지
- 이미지 설명
- 목표 문장
- 핵심어와 문장 성분
- 어휘 단서 단계
- 문법 목표와 선택지
- 허용 가능한 대체 표현
- 초안/검토/게시 상태

## 5. 먼저 결정할 항목

1. 테스트 환자 표시 이름을 `김환자01` 형식으로 사용할지
2. 환자 로그인 아이디를 `patient01` 형식으로 사용할지
3. 환자 내부 이메일 도메인을 `patient.malit.example`로 사용할지
4. 최초 훈련 주제 목록
5. 환자 등록 시 생년 또는 연령 정보를 저장할지
6. 환자에게 첫 로그인 후 비밀번호 변경을 요구할지

위 항목을 확정한 뒤 스키마 수정 → 주제 등록 → 재활사 테스트 계정 → 환자 테스트 계정 순서로 입력한다.
