# 말잇다(MALIT) 프로젝트 기획서

> 실문법적 발화를 보이는 성인 실어증 환자를 위한 단계적 문장 산출 훈련 웹앱

## 1. 프로젝트 개요

### 기획 의도

실문법적 발화를 보이는 성인 실어증 환자는 핵심 단어를 떠올리더라도 조사와 어미를 결합해 완전한 문장으로 표현하는 데 어려움을 겪을 수 있다.

말잇다는 단어 정답을 맞히는 앱이 아니다. 다음 과정을 단계적으로 훈련하여 사용자가 가능한 한 적은 도움으로 문장을 직접 말하도록 돕는 언어재활 보조 웹앱이다.

```text
상황 이해 → 핵심어 인출 → 문장 성분 구성
→ 문법 요소 결합 → 완전한 문장 산출 → 도움 없이 다시 말하기
```

### 핵심 구현 내용

- 상황 그림 기반 문장 산출 훈련
- 어휘 인출 단서와 문법 단서의 단계적 제공
- 단서를 제거한 뒤 전체 문장 재산출
- 음성 인식과 사용자·동반자·재활사의 수동 확인 병행
- 성공 여부보다 `성공에 필요했던 도움의 정도` 기록
- 이전 기록을 기반으로 한 다음 훈련 자동 추천
- 재활사는 최초 설정과 필요 시 검토만 수행
- 노트북·PC 중심의 반응형 웹 제공

### 핵심 원칙

1. 사용자가 스스로 말할 시간을 먼저 제공한다.
2. 약한 단서부터 강한 단서 순서로 제공한다.
3. 정답을 본 뒤에는 단서 없이 다시 말하게 한다.
4. 음성 인식만으로 정답과 오답을 확정하지 않는다.
5. 재활사가 매일 훈련을 편성하지 않아도 된다.
6. 쉽지만 유아적이지 않은 성인 친화적 화면을 제공한다.

## 2. 사용자와 역할

### 환자

실문법적 발화를 보이는 성인 실어증 환자가 핵심 사용자다.

- 매일 추천된 훈련 진행
- 도움 요청과 다시 말하기
- 음성 인식 결과 확인
- 쉬운 훈련 결과 확인

### 언어재활사

재활사는 관리 계정을 사용한다.

- 환자 등록
- 최초 난이도와 훈련 주제 설정
- 제외 주제와 하루 훈련량 설정
- 필요할 때 수행 기록과 추천 이유 확인
- 난이도·주제 수정
- 음성 인식 결과와 수행 기록 수정

재활사는 매일 환자별 훈련을 직접 선택하지 않는다. 최초 설정 이후에는 시스템이 이전 기록을 바탕으로 훈련을 자동 구성한다.

### 동반 훈련 보조자

보호자는 별도 계정이나 전용 화면을 사용하지 않는다. 환자 옆에서 훈련을 돕는 `동반 훈련 보조자` 역할만 담당한다.

가능한 도움:

- 로그인과 훈련 시작 보조
- 마이크 및 화면 조작 보조
- 질문 다시 듣기와 도움 버튼 사용 보조
- 앱이 발화를 인식하지 못했을 때 실제 발화 여부 확인
- 쉬기 또는 훈련 종료 보조

할 수 없는 일:

- 난이도와 치료 목표 변경
- 시스템 추천 수정
- 전문적인 오류 판정
- 상세 재활 기록 열람

동반자가 확인한 결과는 `동반 보조자 확인`으로 저장하며, 재활사의 전문 판정과 구분한다.

## 3. 서비스 운영 구조

```text
재활사의 최초 설정
        ↓
시스템의 첫 훈련 구성
        ↓
환자의 일일 훈련
        ↓
수행 기록 분석
        ↓
다음 훈련 자동 추천
        ↓
필요한 경우에만 재활사 검토
```

### 최초 설정

재활사는 다음 항목만 필수로 설정한다.

| 항목 | 내용 |
|---|---|
| 시작 난이도 | Level 1~3 |
| 훈련 주제 | 식사, 집안일, 가족, 여가, 외출 등 |
| 제외 주제 | 환자에게 부적절하거나 불편한 주제 |
| 하루 훈련량 | 문항 수 또는 예상 시간 |

반응 대기 시간, 집중 문법 요소, 음성 안내 등은 기본값을 제공하고 필요할 때만 수정한다.

### 일일 훈련

환자는 재활사의 당일 설정이나 승인을 기다리지 않고 훈련할 수 있다.

> 오늘 연습할 문장을 준비했어요.  
> 지난번에 연습한 내용부터 천천히 시작해 볼까요?

주요 버튼:

- `오늘의 훈련 시작`
- `다른 주제 고르기`
- `지난 훈련 이어하기`

## 4. 기본 훈련 흐름

목표 문장 예시: **아이가 사과를 먹어요.**

### STEP 1. 상황 이해

한 가지 사건이 명확하게 보이는 그림을 제시한다.

> 그림을 천천히 살펴보세요.

### STEP 2. 핵심어 인출

| 질문 | 목표어 | 역할 |
|---|---|---|
| 누가 있나요? | 아이 | 주어 |
| 무엇을 먹나요? | 사과 | 목적어 |
| 무엇을 하나요? | 먹다 | 서술어 |

사용자가 직접 도움을 요청하거나 일정 시간이 지나면 단서를 제공한다.

### STEP 3. 문장 구성

그림과 함께 인출한 핵심어를 보여준다.

```text
아이 ○
사과 ○
먹 ○○
```

> 이 단어들을 연결해서 하나의 문장으로 말해보세요.

### STEP 4. 문법 요소 결합

```text
아이 + 가
사과 + 를
먹 + 어요
```

빠진 문법 요소가 있으면 해당 부분에만 단서를 제공한다.

### STEP 5. 단서 제거 후 재산출

정답이나 선택지를 숨기고 전체 문장을 다시 요청한다.

> 좋아요. 이제 그림을 보고 문장 전체를 다시 말해보세요.

### STEP 6. 결과 저장

- 핵심어별 성공 단서 단계
- 문법 요소별 성공 단서 단계
- 반응 시간과 재시도 횟수
- 전체 문장 완성 여부
- 단서 제거 후 재산출 여부
- 음성 결과의 판정 주체

## 5. 단서 체계

### 어휘 인출 단서

```text
자발적 인출 → 범주 → 의미 → 선택 → 음운 → 목표어 직접 제시
```

목표어 `아이` 예시:

| 단계 | 단서 |
|---|---|
| 자발적 | 누가 있나요? |
| 범주 | 사람이에요. |
| 의미 | 나이가 어린 사람이에요. |
| 선택 | 어른일까요, 아이일까요? |
| 음운 | 첫소리는 ‘아’예요. |
| 직접 제시 | 아이예요. ‘아이’라고 말해보세요. |

### 문법 결합 단서

```text
자발적 구성 → 빈칸 → 질문 → 전체 선택지
→ 축소 선택지 → 정답 제시 → 단서 없이 재산출
```

목표 조사 `가` 예시:

| 단계 | 화면 또는 안내 |
|---|---|
| 빈칸 | 아이 ○ |
| 질문 | 아이 다음에는 어떤 말이 들어갈까요? |
| 전체 선택 | 은 / 는 / 이 / 가 |
| 축소 선택 | 이 / 가 |
| 정답 제시 | 아이가 |

### 제공 원칙

- 한 번에 하나의 단서만 제공한다.
- 중간 단계에서 성공하면 더 강한 단서는 제공하지 않는다.
- 정답을 직접 보여준 경우 반드시 재산출을 요청한다.
- 도움 요청을 실패로 표현하지 않는다.
- 반복 실패 시 쉬기 또는 문항 종료를 선택할 수 있게 한다.

## 6. 문장 난이도

| Level | 구조 | 예시 |
|---|---|---|
| 1 | 주어 + 동사 | 아이가 자요. |
| 2 | 주어 + 목적어 + 동사 | 아이가 사과를 먹어요. |
| 3 | 주어 + 부사어 + 목적어 + 동사 | 아이가 집에서 사과를 먹어요. |

같은 Level 안에서도 도움 수준을 조절한다.

1. 핵심어와 문법 빈칸 표시
2. 핵심어만 표시
3. 질문만 제공
4. 그림만 제공

문장 Level과 도움 수준은 별도로 관리한다. 어려움이 발생하면 곧바로 Level을 낮추기보다 선택지와 시각적 도움을 먼저 조정한다.

## 7. 자동 추천과 난이도 조절

### 자동 결정 항목

- 오늘의 문장
- 복습 문항과 새 문항의 비율
- 우선 훈련할 어휘·문법 요소
- 첫 단서 수준과 선택지 개수
- 시각적 도움 수준
- 난이도 유지·상향·하향 추천

### MVP 추천 방식

초기에는 생성형 AI의 자유 판단보다 설명 가능한 규칙 기반 추천을 사용한다.

```text
최근 여러 세션에서 자발적 성공이 안정적
→ 시각적 도움 한 단계 감소

특정 조사에서 직접 단서가 반복적으로 필요
→ 다음 훈련에 관련 문장 추가

같은 구조에서 어려움이 반복됨
→ Level은 유지하고 선택지와 시각적 도움 강화

사용자·동반자 수동 확인 비율이 높음
→ 자동 난이도 변경 보류
```

추천마다 이유를 함께 표시한다.

> 최근 ‘을/를’에서 도움이 자주 필요해 관련 문장을 더 넣었어요.

한 번의 결과만으로 난이도를 변경하지 않으며, 변경 폭은 한 단계로 제한한다.

## 8. 음성 인식과 수동 확인

### 기본 원칙

불명확한 발음, 긴 멈춤, 반복, 자기 수정 등으로 음성 인식이 실제 발화를 놓칠 수 있다. 음성 인식은 보조 수단으로만 사용한다.

### 정상 인식

> 이렇게 들었어요.  
> “아이가 사과를 먹어요.”

- `맞아요`
- `다시 말할게요`
- `앱이 잘 못 들었어요`

### 인식이 어려운 경우

> 말을 정확히 확인하기 어려워요.

- `다시 말할게요`
- `말했어요`
- `다른 사람이 확인`
- `도움이 필요해요`

`다른 사람이 확인`은 옆에 있는 동반 훈련 보조자가 실제 발화를 들었을 때 사용한다.

### 판정 구분

| 판정 출처 | 자동 추천 반영 |
|---|---|
| 재활사 확인 | 높은 신뢰도로 반영 |
| 음성 인식 | 인식 신뢰도에 따라 반영 |
| 동반 보조자 확인 | 보통 수준으로 반영 |
| 사용자 직접 확인 | 보수적으로 반영 |
| 판정 불가 | 난이도 판단에서 제외 |

## 9. 기록과 결과

### 주요 기록

- 자발적 핵심어 인출률
- 어휘별 평균 단서 단계
- 주격·목적격·부사격 조사 수행
- 용언 활용과 종결 어미 수행
- 전체 문장 자발 산출률
- 단서 제거 후 재산출률
- 반응 시간과 재시도 횟수
- 판정 출처와 음성 인식 신뢰도

### 환자용 메시지

환자에게는 전문 용어 대신 짧고 부드러운 문장을 제공한다.

| 상황 | 메시지 |
|---|---|
| 혼자 성공 | 혼자서 문장을 완성했어요! 정말 좋아요. |
| 도움 후 성공 | 도움을 살짝 받고 끝까지 말했어요. 잘했어요! |
| 재산출 성공 | 이번에는 도움 없이 다시 말했어요! |
| 도움 감소 | 오늘은 도움을 조금만 받고도 문장을 잘 만들었어요. |
| 추가 연습 필요 | ‘을/를’은 조금 더 연습하면 더 편해질 거예요. |
| 세션 완료 | 오늘 연습을 끝까지 마쳤어요. 수고했어요! |

### 재활사용 결과

재활사 화면에는 전문적인 수치를 제공한다.

- 문장 Level별 자발 산출률
- 어휘·문법 요소별 단서 사용률
- 단서 제거 후 재산출률
- 음성 인식과 수동 판정 비율
- 자동 추천 내용과 추천 이유

### 재활사 화면

1. 환자 목록
2. 환자 최초 설정

4. 자동 추천과 추천 이유
5. 상세 수행 기록
6. 수동 판정 및 수정
7. 콘텐츠 관리

### 공통 하단 영역

환자 화면과 재활사 화면을 포함한 모든 웹 화면 하단에 다음 저작권 문구를 표시한다.

```text
© 2026 이진희. All rights reserved.
```

- 화면의 주요 동작을 방해하지 않는 작은 크기로 표시한다.
- 훈련 화면에서는 콘텐츠와 겹치지 않도록 페이지 최하단에 배치한다.
- 모바일·태블릿으로 확장하더라도 같은 문구를 유지한다.

## 11. 웹 디자인 및 접근성

### 화면 기준

- 초기 환경: 노트북·PC 웹 브라우저
- 디자인 기준: 1440×900
- 최소 지원 화면: 1280×720
- 실제 구현: 고정 크기가 아닌 반응형 웹
- 태블릿·모바일: 향후 확장

환자 훈련 화면은 넓은 화면에서 다음과 같이 구성한다.

- 왼쪽: 큰 상황 그림
- 오른쪽: 질문, 핵심어, 선택지, 말하기 버튼
- 위쪽: 진행 상태와 쉬기
- 아래쪽: 저작권 문구

### 접근성 원칙

- 한 화면에서 한 가지 행동만 요청한다.
- 큰 글자와 충분한 클릭 영역을 사용한다.
- 주요 버튼 위치를 일관되게 유지한다.
- 글자, 그림, 음성 안내를 함께 제공한다.
- 시간 제한이나 카운트다운으로 압박하지 않는다.
- 실패음, 감점, 강한 빨간색 경고를 피한다.
- 색상만으로 상태를 구분하지 않는다.
- 성인을 존중하는 문구와 그림을 사용한다.

## 12. 콘텐츠 설계

### 주제

- 식사와 음식
- 집안일
- 가족과 대화
- 개인위생과 옷 입기
- 취미와 여가
- 외출과 이동
- 장보기
- 병원과 약 복용

### 그림 기준

- 한 그림에 핵심 사건 하나만 표현한다.
- 행위자·대상·동작이 명확해야 한다.
- 불필요한 배경 요소를 줄인다.
- 성인에게 자연스럽고 익숙한 상황을 사용한다.
- 여러 해석이 가능한 경우 대체 표현을 등록한다.

### 문장 기준

- 일상에서 자주 사용하는 문장을 우선한다.
- 어휘 난이도와 문장 구조 난이도를 구분한다.
- 목표 문법과 무관한 표현 차이는 오답으로 처리하지 않는다.
- 자연스러운 조사 생략과 훈련 목표상 필요한 조사를 구분한다.

- 모바일·태블릿 전용 UI

## 15. 기술 방향

### 권장 구성

- Frontend: Next.js + TypeScript
- UI: Tailwind CSS와 접근성 지원 컴포넌트
- Backend: Next.js API 또는 Node.js 서버
- Database: PostgreSQL
- Authentication: 역할 기반 인증
- Storage: 상황 그림 및 동의받은 음성 파일 저장
- Speech-to-Text: 한국어 음성 인식과 수동 확인 병행

### 개발 우선순위

1. 훈련 콘텐츠 데이터 구조
2. 환자용 핵심 훈련 흐름
3. 단계적 단서와 재산출
4. 세션 기록
5. 수동 확인
6. 자동 추천 규칙
7. 재활사 화면
8. 음성 인식 연동

음성 인식보다 훈련 흐름과 수동 확인을 먼저 완성한다.

## 16. 개발 단계

### Phase 1. 근거 조사와 구조 설계

- 실어증 및 문장 산출 훈련 관련 문헌 검토
- 한국어 문장과 조사·어미 훈련 구조 설계
- 자동 추천과 수동 확인 기준 정의

### Phase 2. Figma 프로토타입

- 노트북·PC 기준 환자 화면 제작
- 재활사 최초 설정과 요약 화면 제작
- 도움 요청, 음성 인식 실패, 수동 확인 흐름 연결
- 개발자 시나리오 및 접근성 체크리스트 검토

현재 실제 환자와 재활사를 통한 검토가 어려우므로 이 단계는 `개발자 내부 검토`로 명시한다.

### Phase 3. MVP 개발

- 계정과 권한
- 핵심 훈련 흐름
- 기록과 자동 추천
- 수동 확인과 기본 음성 인식
- 환자 및 재활사 결과 화면

### Phase 4. 전문가·사용자 검토

참여자를 구할 수 있을 때 단서 순서, 대기 시간, 화면 복잡도, 자동 추천 기준을 검토한다.

### Phase 5. 효과 검증

단서 의존도 변화, 새로운 문장으로의 일반화, 일상 의사소통 변화를 확인한다.

## 17. 개인정보 및 안전

- 건강·재활 기록을 민감정보로 취급한다.
- 음성 녹음 전 동의를 받는다.
- 음성 원본 저장 여부를 선택할 수 있게 한다.
- 환자·재활사·관리자의 접근 권한을 분리한다.
- 데이터 삭제와 다운로드 방법을 제공한다.
- 자동 추천을 진단이나 처방으로 표현하지 않는다.
- 재활사가 시스템 판정을 수정할 수 있게 한다.
- 동의 없이 음성 데이터를 모델 학습에 사용하지 않는다.

## 18. 성공 지표

### 제품 지표

- 일일 훈련 시작률과 완료율
- 재활사의 당일 설정 없이 진행한 세션 비율
- 도움 요청과 수동 확인 사용률
- 추천을 재활사가 수정한 비율

### 훈련 지표

- 평균 단서 단계 감소
- 자발적 핵심어 인출률 증가
- 문법 요소별 자발 사용률 증가
- 전체 문장 자발 산출률 증가
- 단서 제거 후 재산출률 증가

### 신뢰 지표

- 음성 인식과 사람 판정의 불일치율
- 판정 불가 비율
- 사용자·동반 보조자 확인 비율
- 잘못된 난이도 변경의 수정 횟수

## 19. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 음성 인식이 실제 발화를 놓침 | 다시 말하기, `말했어요`, 동반자·재활사 확인 제공 |
| 수동 확인의 정확도가 일정하지 않음 | 판정 주체 저장, 추천 반영 가중치 구분 |
| 자동 추천이 지나치게 어려움 | 여러 세션을 기준으로 판단하고 변경 폭 제한 |
| 재활사 설정 부담이 큼 | 최초 최소 설정과 자동 추천 적용 |
| 같은 취약 요소만 반복됨 | 복습·성공·신규 문항을 함께 구성 |
| 사용자가 실패감을 느낌 | 중립적 안내, 쉬기, 감점 표현 제거 |
| 자연스러운 한국어를 오답 처리함 | 대체 표현 등록과 재활사 수정 제공 |
| 임상 효과를 과장함 | 내부 검토와 임상 검증을 명확히 구분 |

## 21. 최종 방향

말잇다의 성공 기준은 문제 수나 단순 정답률이 아니다.

> 같은 문장을 이전보다 적은 도움으로 말할 수 있는가?

> 도움을 제거한 뒤에도 스스로 문장을 다시 만들 수 있는가?

> 연습한 문장 구조를 새로운 상황에서도 사용할 수 있는가?

재활사는 최초 설정과 필요한 시점의 판단에 집중한다. 환자는 매일 독립적으로 훈련하고, 시스템은 이전 기록을 바탕으로 다음 과제를 자동 구성한다.
